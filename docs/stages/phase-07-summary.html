1. 阶段目标与前阶段问题

阶段六的配置版本可以固定每个 Run 的系统提示词、模型参数、工具权限与 Worker 契约，但跨 Run 没有独立的长期记忆：单次对话只保存在该 Run 的消息历史和检查点中。阶段七在不替换 Agent Runtime / Workflow 控制循环的前提下，添加可显式管理、可审计、可检索的偏好/事实记忆，并让 Run 使用固定的记忆快照。

本阶段范围由用户确认：当前单一受控 CLI 操作者；只在明确的记忆管理命令上写入；新 Run 自动检索少量相关记忆；协作任务只把需要的信息放进相应上下文。交付按“实现验收—远端 CI/镜像发布—L5 部署”闭环完成。

2. 本阶段实现内容

  • 新增 PostgreSQL 结构化记忆表 agent_memory，保存 namespace、key、类型、正文、版本和活动状态。Flyway V13 加入 metadata-only 的 agent_memory_event；事件不含 key/正文且由数据库触发器禁止修改或删除。
  • MemoryService 提供显式记忆新增、查找、列表、更新、删除和 Run 创建时的检索快照。默认最多 500 条活动记忆；同一 namespace 的新增通过 advisory lock、唯一索引和事务内计数共同执行。
  • 删除采用 tombstone：活动表清空 key 与正文并留下版本事件，允许之后重用 key。更新/删除使用版本 CAS，操作记录与内容修改在同一事务提交。
  • 确定性检索使用 Unicode NFKC 规范化、key 精确命中优先、英文词项和中文相邻二元组重合排序；最多选择 5 条，注入文本最多 2000 个 Unicode 码点。检索失败返回空的 degraded 快照以继续任务；管理写失败受控报错。
  • 同步 Run、协作 Run 和后台队列 Run 都在首次落盘前固定 MemoryContextSnapshot。RunStore 保存快照；恢复继续使用已持久化内容，不会再次查询当前记忆库。旧检查点无此字段时按空快照处理。
  • 单 Agent、Supervisor 规划/汇总及协作 NO_SPLIT fallback 可获得快照。子 Worker 的模型请求不注入父级完整记忆，只接收计划明确解析的任务输入与依赖结果。
  • CLI 新增 /memory help|list|show|remember|update|delete。普通自然语言中的“记住”不会直接写入记忆。
  • 新增低基数 Micrometer 计数器和耗时指标，只含固定 operation/result 标签；不把 namespace、key、query、正文或异常内容写入日志、指标标签或记忆审计事件。

4. 设计选择与替代方案

决策主要替代方案采用原因与适用边界
结构化 PostgreSQL 记忆向量数据库、独立 RAG 服务、LLM Wiki首个场景是可确认的偏好/事实，需版本、显式删除和可审计；固定规模下结构化表更简单。文档检索和语义检索不是本阶段目标。
只通过显式管理命令写入模型从普通对话自动提取并保存避免误记和静默持久化；CLI 没有可信用户身份，因此本版只支持单一受控 namespace，不宣称用户级隔离。
确定性词面检索向量 embedding / reranker / RAG少量结构化偏好可用有界、可重复检索，无需额外模型调用；代价是不能保证语义召回，后续应以评测数据证明需要再引入检索增强。
Run 固定快照每轮请求都读取“最新记忆”恢复请求上下文不随记忆更新而改变，方便追溯；删除只影响后续 Run，历史 Run 快照依现行 Run 保留策略留存。
Supervisor 可读，Worker 最小输入把父上下文/所有记忆广播到每个 Worker减少不相关信息传递并保持既有子任务边界；Worker 只收到计划明确派发的字段与依赖结果。

5. 实际效果与可重复验证

新 Run 会按输入查询最多 500 条活动记忆候选并把最相关的最多 5 条固定到 Run；向模型注入的完整提示文本受 2000 Unicode 码点上限约束。运行途中更新或删除记忆不会修改已保存 Run 的快照。PostgreSQL 集成测试覆盖 V13 迁移、同 key 冲突、删除后复用 key、版本并发、namespace 并发上限、审计 append-only、内容更新事务回滚，以及 Run 检查点中的快照往返。

本阶段没有真实 Provider 质量测试。确定性与持久化范围由 Fake、Testcontainers 和模型 stub 覆盖，不能证明真实模型一定遵从偏好或事实正确。

6. 尚存限制与后续方向

  • 当前 CLI 操作者标识不是认证身份；单 namespace 默认值不提供用户、团队或租户隔离。真实接入前需定义可信身份与读写授权边界。
  • 词面检索容易漏掉语义相关条目；没有向量索引、事实冲突消解、自动来源抽取或 LLM Wiki。
  • 删除记忆不删除已持久化 Run 快照；Run 自动保留/删除目前依既有策略处理，默认自动清理关闭。若需要主体级删除，需要单独设计快照索引和删除流程。
  • 记忆内容会进入模型请求；向 DeepSeek 发送前仍受项目现有数据处理边界约束。当前凭据模式检测只能拒绝部分常见密钥字面量，不能替代人工数据定级。
  • 当前固定回归验证的是有限规则和数据边界，不代表记忆准确率、真实回答质量、语义检索召回率或生产可用性。
  • L5 启动期间两只新 Pod 各出现过一次短暂 Startup probe 告警，随后均 Ready、无容器重启；后续需持续观察较慢启动时的探针裕度。

下一步应先基于实际调用场景和固定评测样例判断是否需要更强的语义检索、来源管理或身份域隔离，再拆分相应目标；不默认引入 RAG 或自动记忆抽取。
