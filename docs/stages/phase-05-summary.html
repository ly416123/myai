1. 阶段目标与上一阶段遗留问题

阶段四交付了可持久化、可复现、可比较的评测生命周期；协作 Worker 仍在应用启动时静态配置。阶段四结束时，Worker 定义没有必需输入/可选输入和输出契约，子任务计划没有显式表达业务输入字段及来源。Supervisor 主要靠模型从自然语言猜测子任务需要什么，运行前无法机械检查必填信息，Worker 结果也没有统一结构可供下游任务校验。

这会让相同 Worker 随任务、模型提示词变化而接收不同背景，也可能让父任务把未验证的输出传给依赖任务。阶段五把能力定义、任务输入和交付物固定为可校验的数据契约，同时保留既有共享预算、租约、fencing、工具权限与未知副作用不重放语义。

2. 本阶段交付

  • 静态 Worker 契约：WorkerSpec 加入版本、输入/输出 Schema、短职责与输出摘要及能力标签；启动时检查重复 ID、非法 Schema、远程 Schema 引用和未知工具引用。
  • 规划与依赖绑定：Supervisor 只收到规划所需的 Worker 能力摘要和输入/输出字段信息；计划保存验收条件、Worker 版本和字段绑定。输入只允许来自父请求提取值，或同一 DAG 中直接依赖任务的 JSON Pointer 输出。
  • 派发前校验：程序检查 DAG、依赖、必需字段、来源与 JSON Schema。所有字段完成解析并通过输入 Schema 前，不启动 Worker；已解析输入和初始 Worker 消息先保存到 Run 检查点。
  • 上下文隔离与结构化交付：Worker 只接收绑定后的输入、任务目标、验收条件及其直接依赖结果。Worker 最终答案必须是符合输出 Schema 的 JSON object；通过验证后才保存为结构化结果供父 Workflow 汇总或下游绑定。
  • 版本恢复语义：执行与恢复都核对保存的 Worker 版本。契约版本不同或已持久化计划/执行投影不完整时 fail closed，使用脱敏、机器可读的契约错误，不重新解释输入，不调用模型或工具。
  • 可观测上下文尺寸：RunRecord 保存规划消息内容的 UTF-8 字节数。确定性 Fake 样例测得 1,356 字节；测量不含 SDK 请求序列化/传输开销，且没有同构历史样例，因此不据此声称 Token、延迟或费用下降。

5. 关键设计选择

选择替代方案采用原因与边界
启动时静态 WorkerRegistry数据库动态注册中心、实例心跳和服务发现需求明确限定静态能力契约；不引入新服务或维护面。实例选择、容量感知和动态扩缩容仍未覆盖。
Worker 级契约 + 工具级 Schema 分离把全部工具参数并入一份“Worker 总 Schema”Worker 契约描述业务任务输入和交付物；工具注册表继续维护各工具自己的参数 Schema，避免职责混淆。
父请求仅按绑定字段传递复制完整父对话，或自动摘要所有历史降低无关背景泄漏和上下文增长；阶段五不做自动摘要、向量检索或父子全量消息合并。
JSONB 检查点保存兼容字段新增关系表和 Flyway 迁移当前存储已用整体检查点并提供查询投影；新增字段可纳入现有 payload，避免阶段五扩大数据库模型。File/JSON 与 PostgreSQL 往返测试验证持久化。
Draft 2020-12 JSON Schema，拒绝远程 `$ref`仅依赖模型提示约束或自制字段校验器复用已有 validator 依赖，在程序边界做确定性输入/输出检查；schema 不访问远程资源。

7. 已知限制与下一步

  • 父请求是自由文本。模型可提取候选输入值，程序校验字段和类型，但系统不能证明提取值在语义上真实来自用户原文；后续需要更强的来源引用/校验策略时再单独设计。
  • Worker 能力定义为启动时静态装配，不含动态实例注册、健康心跳、容量感知、能力池负载均衡或多集群调度。
  • L5 检查验证应用启动、数据库连接/版本、基础指标和平台健康，未运行真实模型或完整协作请求；阶段行为由 Fake 和确定性测试验证。
  • GitHub `publish-images` 仅在默认分支 push 后执行；阶段五 feature branch 只完成 CI verify/build/scan。真正发布 GHCR 镜像需在未来获授权的主分支发布流程完成后再次核对 Registry digest。
  • Schema 合法不代表任务结果正确；1,356 字节是一个固定测试样例的消息内容基线，不代表通用上下文优化或 Agent 整体质量保证。
  • 现有工具的外部副作用 exactly-once 语义未改变；Worker 契约不提供幂等协议、事务或补偿机制。HTTP API 与生产身份认证/授权仍按项目范围暂缓。

后续阶段应先确认业务目标，再决定是否需要 Worker 运行时注册/能力池调度，或面向调用方的任务查询与通知接口；本总结不自动把这些列为下一阶段承诺。
