1. 阶段目标与上一阶段遗留问题

阶段四把阶段二、三已有的 Fake 回归集和真实 Provider Runner 从“单次运行后生成本地报告”扩展为可持久化和可对比的评测实验。保持 Agent 控制循环与工具协议不变，不引入 Langfuse、评测平台或新的常驻服务。

  • 阶段三已有固定 Fake 样例、版本化数据集和人工/短语断言，但没有稳定的 Evaluation ID、统一 Evaluator 版本清单或 PostgreSQL 跨次结果查询。
  • 真实评测主要依靠本地 JSON 文件和每个 Agent Run 的持久化；报告不能通过统一的 dataset hash、Evaluator manifest 和执行模式判断是否可比较。
  • 用例执行中断后没有独立的实验/用例状态、并发 claim 或明确的不重放边界。

这些缺口使历史结果难以复现与关联，也让进程中断时无法区分已完成、未开始和模型结果未知的用例；阶段四围绕这些问题新增实验生命周期，而没有重写 Runner 或 Workflow。

4. 实现与设计决策

决策实现与原因主要替代方案
复用 PostgreSQL + FlywayV7 增加 evaluation_run、evaluation_case、状态事件和执行租约，减少新平台/服务；评分通过 Run 外键关联，删除 Run 时只清空链接并保留评测分数。本地 JSON 文件无法可靠多进程 claim；新增评测平台增加部署与数据流范围，阶段四不采用 Langfuse。
单执行者 lease + fencing状态条件更新选出唯一 owner，后台心跳续租；恢复要求 Deadline 和 lease 都已过期，事务终结当前实验并提升 fence，旧 owner 无法写入。只看 Deadline 无法识别活跃执行者；自动重放会重复费用或外部副作用。
确定性 EvaluatorEvaluator 有稳定 ID/version；支持 Run 结果、工具选择、协作计划、短语断言、预算、结构化 JSON Schema 和预期失败类别。Schema 在 DatasetLoader 阶段编译，只允许文档内引用。LLM-as-a-Judge 波动且另有费用，不能作为本阶段确定性门禁。
最小持久化与脱敏导出数据库只保存数据集身份、模型元信息、状态、评分、调用/Token/耗时和 Run ID，不复制 prompt、answer、工具参数；JSON 导出为 DTO 序列化且字段/map 顺序稳定。复制完整对话便于 UI 浏览，但扩大敏感正文复制面，本阶段不做。
先真实 Provider CLI，CI 只 Fake保留 `AGENT_EVAL_ENABLED=true` 显式开关；真实运行有案例/模型/工具/Deadline 预算。JUnit 和 CI 使用 Fake 模型与确定性数据。普通 CI 真实模型调用会产生费用、暴露数据并引入非确定性。

5. 效果与实测

  • DatasetLoader 生成稳定 `datasetId/version/formatVersion/contentSha256`；空白和 JSON Schema object 属性顺序不改变规范化哈希。未知 Evaluator、无效/远程 Schema 引用在模型调用前拒绝。
  • PostgreSQL 对同一 evaluation 做原子 claim；case 终态写入只成功一次。删除被关联 Run 后评分仍在。状态时间写入 `evaluation_status_event`。
  • 比较器拒绝数据集哈希、Evaluator manifest、Workflow 模式、case/score 集合不一致以及 `CREATED/RUNNING` 实验；报告逐 Evaluator 的 pass/fail/unknown 变化、工具选择观察、Token 覆盖、调用数、费用估值以及 duration 样本均值/中位数/p95/min/max。
  • 评测 spans 关联 `evaluationId/caseId/runId` 为高基数 Trace 属性，不增加 Prometheus 标签。未知 Token、费用或耗时保持未知。
  • 本地阶段总结没有收集真实模型质量新数据；小型 Fake 结果只能证明已实现分支的行为，不代表生产质量或统计显著性。

7. 限制、风险与下一步

  • Lease fencing 可阻止已失租的 owner 继续写评测记录或推进下一 case，但不能撤销供应商已接受的模型请求、取消外部工具副作用或避免网络分区期间已发出的费用。没有工具幂等键/事务协议时不保证 exactly-once。
  • 状态 lease 续租依赖本进程调度线程和数据库可用性；数据库连接中断会让当前执行失去写权限。需要等待 deadline 与 lease 都过期后再恢复。测试覆盖 lease 过期和 stale owner 拒写，但没有压力测试长时间数据库中断/调度停顿。
  • 时延摘要只描述每次实验有限样本的均值、分位数和样本数，不做显著性检验，不设伪造性能阈值。固定数据集也不能代表真实用户分布。
  • 评测历史没有自动清理策略，按项目决定持续保留；Run 正文仍受现有 RunStore 保留配置影响。L5 当前代码未部署，数据库 schema 的现场版本仍需下次连通后确认；历史可确认版本为 v6。
  • 本阶段没有 HTTP API、生产认证授权、Web UI、Langfuse、外部通知或新评测平台；这与“评测引擎 + PostgreSQL 持久化 + CLI”的范围一致。
  • 下一步建议：L5 恢复可达后先只读确认 schema 和资源，再决定是否发布含 V7 的应用；后续再结合已批准数据分类和保留策略评估真实模型集、成本门槛和多次运行统计方法。
