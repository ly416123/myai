阶段一整体分层架构

时间点与范围：本图回溯项目最初的基础 Agent 阶段。现存 Git 历史无法独立确认阶段一的准确完成日期和最终源码快照，因此图只表达可由最初需求及当前保留职责边界确认的形态，不把后续阶段能力倒填进来。本图不含 RunStore、检查点恢复、Supervisor–Worker、PostgreSQL 或 Kubernetes 部署。模型根据消息和工具定义选择工具，Runtime 不按用户输入关键词分流。

职责边界

  • Main / CLI：接收用户输入、组装或调用应用对象，并展示执行过程。
  • AgentRuntime：拥有 Agent 决策控制循环；处理普通回答、一个或多个工具调用、工具结果回填和模型调用上限。
  • ModelClient：隔离 DeepSeek/OpenAI 兼容 SDK，输入统一消息和工具定义，输出统一的文本或工具调用响应。
  • AgentTool / ToolRegistry / ToolExecutor：描述可用能力、按名称查找工具、校验 JSON 参数并调用本地 Java 方法。
  • MessageContext：在一次任务期间维护消息历史；阶段一不提供跨任务持久化。

本阶段边界与证据说明

该阶段的目标来自项目最初需求：使用 Java 21 与 Maven 自行实现最小 LLM + Tool Calling Agent，不引入 Agent 框架；保留 ModelClient、工具契约和 Runtime 控制循环边界。阶段二随后扩展了 Run 状态、Checkpoint、预算与恢复。
