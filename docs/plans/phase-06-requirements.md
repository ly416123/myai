## 1. 背景与目标

阶段四建立了离线、显式触发的评测实验，能够在固定数据集和 Evaluator 上比较 Agent 变更。评测结果可以回答“候选版本在这组用例和规则下是否退步”，但它本身不管理生产配置版本，也不能发布、灰度或回滚配置。

本需求希望补齐从候选配置到生产生效的受控生命周期：版本化提示词、Skill 引用、模型及运行参数和工具权限；将发布与阶段四评测结果关联；可查询发布历史并回滚；运行中的每个新 Run 动态读取当前已发布版本，同时固定该 Run 使用的配置快照。

本需求范围内的“动态加载”指**新 Run 无需重启应用即可采用新配置**。不得在一个 Run 执行期间更换其提示词、Skill 或模型参数，避免同一个工作流中途漂移。

## 2. 术语与对象

- **Agent 配置修订（Revision）：** 不可变的配置内容及规范化内容哈希，包括系统提示词、Skill 内容或不可变引用、模型标识与非敏感参数、Worker 能力/契约引用、允许的工具集合和格式版本。Secret 只保存引用，不保存 Secret 值。
- **发布（Release）：** 经验证后可被运行时引用的不可变修订，包含修订 ID、内容哈希、来源提交、评测实验引用、发布说明和创建时间。
- **激活指针（Active Assignment）：** 某个环境/Agent 当前使用的 Release 选择。更新指针必须产生审计事件，不修改 Release 本体。
- **运行快照（Run Snapshot）：** Run 创建时解析并固定的 Release ID 与哈希，以及其实际配置版本。后续激活变化不改变已创建 Run。
- **发布事件（Release Event）：** 创建候选、评测通过/拒绝、审批、激活、灰度调整、回滚等不可覆盖的历史记录。

## 3. 版本管理与历史

1. 提示词、Skill、模型设置、工具权限及与 Worker 契约相关的运行配置应形成可复现的版本包，并生成稳定版本 ID 与规范化 SHA-256。
2. 已发布版本不可原地编辑。任何内容变更都创建新修订；加载时校验 Schema、引用完整性、工具权限和哈希。
3. 记录来源 Git commit、构建/发布主体、创建时间、评测基线和候选 Evaluation ID、评测结果、审批/激活/回滚操作者、目标环境及变更原因。不得记录密钥、认证头或 Secret 内容。
4. CLI 至少支持列出版本和发布历史、查看两个修订的差异、查看当前环境激活版本、查看某个 Run 使用的版本、查看关联评测结果和发布事件。
5. 评测历史与发布历史保持不同实体，并通过 ID 关联：Evaluation 表示一次离线测试；Release 表示一份可部署配置；一次 Release 可以引用一个或多个评测实验。
6. 历史版本及其引用的 Skill/模型配置必须遵守保留规则；删除前检查是否仍被 Run、发布、回滚点或评测记录引用。未确认保留期限前不自动清理审计历史。

## 4. 离线评测门禁与发布

1. 候选配置可引用阶段四兼容的离线评测实验。发布前显示数据集哈希、Evaluator manifest、运行模式、候选/基线差异和失败用例。
2. 发布策略由明确、版本化的规则组成，例如指定 Evaluator 不得回归、关键用例必须通过。不得把未定义的主观质量分或小样本耗时伪装成门禁。
3. 若数据集、Evaluator 或运行模式不兼容，必须标注不可直接比较；除非另有明确审批策略，不得仅凭不兼容实验自动放行。
4. 评测通过是候选发布的证据，不等于真实流量质量保证。发布记录应保留候选配置、基线版本和门禁判定，便于事后复核。
5. 发布与激活分离。创建候选版本不影响生产；只有完成受控激活后，新 Run 才可读取该版本。

## 5. 动态加载、灰度与回滚

1. Runtime 在每个新 Run 开始时解析环境/Agent 的有效 Release，并持久化 Run Snapshot。该过程应保证多副本 Worker 得到同一激活版本，且数据源、缓存与激活更新具备明确的一致性边界。
2. 配置解析失败、哈希不匹配、依赖缺失或版本不兼容时，必须拒绝启动新 Run 并产生稳定错误；不得静默回退到未记录的本地默认值。已有 Run 继续按其固定快照执行。
3. 支持通过一次原子激活切换到新 Release；回滚通过重新激活既有不可变 Release 完成，同时写入操作者、时间、原因和触发依据。不得删除失败版本或覆盖其历史。
4. 支持受控灰度：按明确、稳定的路由键将新 Run 分配到候选版本，并让同一会话/工作流保持版本粘性。分流比例、范围、开始/结束时间和观测窗口均需记录。
5. 灰度键必须来自可信的调用上下文。当前 `CallerContext` 的 `local-cli` 标识未认证，不能当作用户/租户身份或授权依据；在可信身份源和授权策略未就绪前，只能采用受控的环境/实例级灰度，不得按伪造的用户标识分桶。
6. 自动回滚只能依据预先批准且可观测的客观阈值执行，例如错误率、关键 Run 成功率或已定义的确定性 Evaluator 失败率；阈值、最小样本量、窗口、冷却时间和恢复策略必须显式配置并审计。缺少足够样本或数据时应停止自动决策并告警/转人工，不得推断质量正常。
7. 发布控制不得依赖同步调用模型评审来阻塞普通用户请求。阶段四离线评测用于发布前门禁；生产 Trace 在线评测若后续启用，应与业务响应解耦、限制采样与预算，并先完成数据最小化、脱敏和保留策略审查。

## 6. 在线评测：后续候选，不属于本次确认范围

当前阶段四属于离线批量评测，不会自动抽样或评分线上请求。业界常见的在线评测方式是在生产 Trace 上持续或按筛选条件抽样运行 Evaluator，并把评分附回 Trace；常见用途是发现离线数据集未覆盖的问题、观察质量趋势，再由人工复核后沉淀为新的离线用例。低成本的结构/错误/预算规则可用于运行监控；语义 Judge 或人工标注通常需要单独的异步队列、采样率、成本上限和数据保护边界。

本节仅记录后续讨论方向，**不授权采集生产提示词、回答或工具参数，也不构成阶段六必须交付的在线评测实现**。若需纳入阶段六，应另行明确生产数据来源、授权与脱敏、采样单位/比例、模型费用预算、持久化字段、保留期限、人工复核和故障隔离方式。

## 7. 运维接口与权限边界

1. 初期继续使用受控 CLI/发布流水线完成配置修订、验证、审批和激活；本需求不自动新增 HTTP API 或 Web UI。
2. 生产激活应由受信任的部署身份执行，并通过现有基础设施访问控制保护。由于项目尚无生产认证授权，阶段实现必须先明确由 CI/CD 身份、Kubernetes RBAC 或其他已批准控制面承担的权限边界；`local-cli` 不能被视为生产管理员身份。
3. 激活操作应具备并发保护和幂等键，避免两个发布者覆盖彼此的环境指针；失败时保持旧版本有效并返回可审计结果。
4. 发布状态、激活版本和回滚事件纳入日志/Trace/指标；高基数 Release ID 可用于日志和 Trace，不得作为 Prometheus 标签。
5. 配置数据库/注册表不可用时，新 Run 如何降级必须明确。默认安全策略是拒绝使用无法追溯的配置启动新 Run；已有 Run 不因新配置读取失败而改变快照。

## 8. 验收要求

- 相同输入配置生成稳定哈希；任何修订变更都会生成新版本，发布后内容不可变。
- 敏感信息扫描/契约测试证明 Secret 值不会进入 Release、日志、Trace、评测报告或导出文件。
- 新 Release 与兼容离线 Evaluation、基线 Release、门禁规则及最终决策可互相追溯。
- 激活切换原子可见；并发激活、数据库失败、非法配置和哈希不一致均不会让 Worker 静默采用未知配置。
- 两个及以上 Runtime 实例在激活切换前后，对新 Run 使用版本一致；已启动 Run 始终沿用原 Run Snapshot。
- 回滚会重新激活指定历史 Release，生成完整事件；回滚后新 Run 使用目标旧版本，历史 Run 的配置快照不变。
- 灰度分配可重复、稳定且可统计；可信路由键未就绪时，验证按用户/租户的灰度不可启用。
- 自动回滚测试覆盖最小样本不足、阈值触发、窗口边界、重复触发和激活失败；只在明确的、经过批准的确定性条件下执行。
- 受控测试覆盖新 Run 动态读取、缓存一致性、发布竞态、Worker 重启和中断恢复；不得声称具备 exactly-once 或零切换延迟，除非有相应证据。
- 若阶段六最终纳入在线评测，必须另有独立验收：采样率/过滤、异步隔离、失败不影响用户响应、限额、脱敏/保留以及评分回链均有测试和运行证据。

## 9. 明确不纳入本候选需求

- 不修改 Agent Runtime 的核心控制循环，不自动把每个生产请求创建为离线 Evaluation。
- 不把 Evaluation ID 与 Release ID 混为同一种对象。
- 不在 Run 执行途中热替换提示词、Skill、模型或工具权限。
- 不保存模型密钥、认证头或 Secret 明文，不默认持久化完整提示词/回答/工具参数到发布记录。
- 未另行批准前不采集生产对话、不自动训练或改写 Prompt/Skill、不自动部署由模型生成的配置。
- 不承诺仅凭离线评测或在线 Judge 分数即可保证生产质量。

## 9.1 实现与验收边界

- 本阶段已实现独立 Release 审批记录；由于当前没有生产认证授权，`local-cli` 仅作为流程审计字段，不证明操作者身份，也不构成双人审批或生产访问控制。
- 自动回滚默认关闭。启用后以灰度候选 Run 的终态失败率作为操作阈值；它不评估语义质量，不构成质量保证。样本不足、扫描页达到上限或冷却期内均不触发回滚。
- 本机完整验收使用 Fake/确定性测试和 Testcontainers PostgreSQL，不访问真实模型或密钥。PR 验证、分支候选镜像发布和 L5 候选部署验收均已通过；L5 候选版不是 `main` 正式镜像，PR 仍等待审批。
