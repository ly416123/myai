2. 核心接口与数据

少量稳定的数据类型连接模型、运行时和工具。

ModelClient

输入消息列表和工具定义；输出 ModelResponse。Runtime 只依赖接口。

ModelResponse / ToolCall

区分普通文本与工具调用；调用保留 id、工具名和 JSON 参数。

Message

表示 user、assistant、tool 等角色，保留工具调用与结果的关联信息。

AgentTool

统一提供 name、description、inputSchema 和 execute。

ToolRegistry

负责注册、按名称查找工具，并导出给模型的工具定义。

ToolExecutor

查找、校验、执行工具；将成功或异常包装成结构化 ToolResult。

MessageContext

维护单次任务的消息历史；第一版只存在内存中。

AgentRuntime

手写循环，处理多工具调用、结果回填和最大模型调用次数。

演示工具

本地计算器、按时区取当前时间、返回固定模拟天气。

参数校验先覆盖演示工具需要的 JSON Schema 类型、必填字段与基础范围；不引入大型校验框架。

3. 一次完整调用时序

工具由模型根据对话与工具描述选择，Java 不按关键词分流。

用户输入问题CLI 创建本次任务的 MessageContext，追加 user 消息
↓
模型调用 #1：消息历史 + 工具定义ModelClient 将统一请求映射到厂商 SDK
↓
模型返回工具调用（可一次多个）
记录 assistant 工具调用消息保留每个调用的 ID、名称、参数
模型返回普通回答
作为最终答案返回 CLI任务完成
↓
ToolExecutor 逐个执行所有调用按名称查找 → 校验参数 → 执行 Java 方法 → 捕获错误
↓
将每个 ToolResult 作为 tool 消息追加到上下文结果通过原工具调用 ID 与请求对应
↓
再次调用模型模型可继续请求工具；重复以上过程，直到返回普通回答
循环边界：总模型调用次数最多 10 次（包含首次调用）。达到上限仍未得到最终回答时，Runtime 以明确的受控错误结束。

4. 对照传统 Java 后端

Agent Runtime 可以理解为一次由模型参与决策的应用层工作流。

传统后端里的相似角色

  • ModelClient：第三方服务客户端 / Adapter
  • AgentTool：业务能力接口
  • ToolRegistry：能力注册表
  • ToolExecutor：带校验和错误转换的应用服务
  • MessageContext：单次请求的上下文状态
  • AgentRuntime：应用层编排器 / 工作流控制器

若改用 Spring AI

  • 模型请求与消息类型由 ChatClient、Prompt 和 Message 抽象承担
  • 工具定义可通过其 Tool Calling 机制注册
  • 模型响应解析和部分工具调用编排由框架协助
  • 本项目保留自写循环，以便学习每次请求、执行与消息回填
